# 12_photo_gallery — 反射屏无线相册

本例为 Arduino 课程的 **Demo12：无线图库**；当前不提供对应的 ESP-IDF 版本。

面向 ESP32-S3 RLCD 4.2。设备自己开一个 Wi-Fi 热点，手机浏览器上传照片，RLCD 屏幕立刻显示。全程不需要路由器、不需要外网、不需要 App，也不需要在设备上解码 JPEG：像素转换全部在手机浏览器里完成，固件只搬运已经打包好的黑白位图。

沿用 03/04 的自研 ST7305 驱动、09 的 SDMMC 接线和 11 的按键去抖，不依赖 LVGL、U8g2 或任何图像库。

## 烧录与使用

1. 断电插入 FAT32 MicroSD 卡（可选，但强烈建议）。不插卡也能用，只是只能存 1 张临时照片。
2. 打开 `12_photo_gallery.ino`，选择 ESP32S3 Dev Module：USB CDC On Boot Enabled、Flash 16MB、OPI PSRAM、QIO、Huge APP（与项目其它示例一致）。
3. 首次启动或没有有效照片时显示帮助页：热点名、密码和访问地址；已有 SD 照片时恢复选中照片，记录无效则显示第一张有效照片。串口 115200 也会打印 `SSID=RLCD-Gallery password=12345678 URL=http://192.168.4.1`。
4. 手机连接热点 **RLCD-Gallery**，密码 **12345678**。系统提示「无法访问互联网」时选择保持连接——这是设备自己的热点，本来就没有外网。
5. 浏览器打开 <http://192.168.4.1/>（会自动跳转到首页）。选一张照片，页面立刻显示这张照片在屏幕上真正会呈现的样子，可以先调抖动/二值、填充/留白、亮度和对比度。
6. 点「上传并显示」：照片送到设备，屏幕刷新，相册里出现新的缩略图。

上传一张约 15KB，完成时间取决于网络、SD 写入和屏幕刷新。上传和手动切换照片都会把幻灯片模式重置回「手动切换」，需要时再选一次时长。

## 按键

| 操作 | 效果 |
| --- | --- |
| 短按 BOOT（GPIO0） | 上一张（在帮助页时切回照片） |
| 短按 KEY（GPIO18） | 下一张 |
| 长按 KEY（约 0.7 秒） | 回到帮助页，并退出幻灯片 |
| — | 幻灯片到点时自动切下一张 |

没有任何照片时，`nextPhoto()` 不会空转，屏幕停在空白/帮助页。相册里被判定为损坏的文件会被跳过，不会卡住翻页。

## 存储：SD 模式与临时模式

开机时 `GalleryStore` 尝试 `SD_MMC.setPins(38, 21, 39)` + 1-bit 挂载。挂载成功就是 **SD 模式**，失败就是 **RAM 临时模式**，屏幕和页面都会明确写出当前模式，不会假装照片已经保存。

本例只使用 SD 和 RAM；无卡时仅保留一张临时照片，断电丢失。无需为相册更改分区表或擦除设备数据。

| | SD 模式 | 临时模式 |
| --- | --- | --- |
| 容量 | 24 张（`GALLERY_MAX_PHOTOS`） | 1 张 |
| 目录 | `/gallery13/P01.rlcd` … `P24.rlcd` | 只有 RAM 缓冲 |
| 断电 | 保留，含当前选中张号（NVS `gallery13/selected`） | 全部丢失 |
| 删除 | 删文件，槽位可被下一次上传复用 | 只清当前缓冲 |

SD 模式下每张是完整的数据包：4 字节 `RLG1` + uint16 宽 + uint16 高 + uint32 负载长度 + uint32 CRC32 + 15000 字节位图 = **15016 字节**。写入时先写 `/gallery13/upload.tmp`，整包回读逐字节比对，再用 rename 提交，以降低不完整文件成为正式照片的风险。这不是任意掉电时刻的数据完整性保证，上传保存期间不要断电或拔卡；如果外部已经放了同名文件，本次上传会失败而不是覆盖它（返回 500 和 `SD save / verification failed; previous photos preserved`）。

位图格式：400×300 行优先，每行 50 字节，MSB 在前，bit 1 = 黑。整数一律小端。CRC32 就是标准 IEEE 多项式（0xEDB88320），和 zlib / 页面里的 JS 实现一致。

## 相册协议

手机前端只通过下面这几个接口和设备说话：

| 接口 | 说明 |
| --- | --- |
| `GET /` | 画廊页面（`gallery_web.h`，PROGMEM 内嵌） |
| `GET /image.js` | 前端像素处理脚本（`gallery_image.h`） |
| `GET /api/status` | SSID、IP、持久化、屏幕就绪、帮助页可见、容量、当前张、幻灯片秒数、`items[{id,valid,crc}]` |
| `GET /api/frame?id=N` | 该照片的 15016 字节数据包，供页面画缩略图 |
| `POST /api/upload` | multipart 上传，字段名固定 `frame`，只接受一个文件 |
| `POST /api/select?id=N` | 让屏幕显示第 N 张，并退出幻灯片 |
| `POST /api/delete?id=N` | 删除第 N 张；删掉当前张后自动显示下一张有效照片，没有就回到帮助页 |
| `POST /api/slideshow?seconds=` | 只接受 `0`（手动）、`10`、`30`、`60` |
| `POST /api/info` | 屏幕回到帮助页 |

所有状态响应都带 `Cache-Control: no-store`；除图片数据外一律 JSON，成功是 `{"ok":true}`，失败是 `{"error":"中文原因"}` 并带合适的 HTTP 状态码（400 编号/数据不对、404 不存在、409 相册已满、413 数据过大、500 SD 写入失败、503 屏幕未就绪）。挂在别的路径上的请求会 302 回首页，这样手机上手动输错地址也不会看到空白页。AP 上还跑了一个 DNS 服务器把 `*` 都指回 192.168.4.1（captive portal）。

## 为什么设备端不需要解码图片

`gallery_image.h` 里的 `kGalleryImageJs` 是纯前端实现：亮度加权灰度、亮度/对比度、Floyd–Steinberg 抖动（奇偶行蛇形扫描，避免规则纹路）、位打包、CRC32，以及 `packet()` 组包和 `decode()` 解包。手机端的处理流程是：

1. 支持 `createImageBitmap` 时先尝试降采样到 800 像素宽，失败后尝试原尺寸解码；不支持该接口时使用 `new Image()` + `objectURL`。浏览器仍无法解码时会提示换图；
2. 按「填充裁切」或「完整留白」缩放并居中画到 400×300 的离屏 canvas，canvas 预先填白，所以 PNG 透明区域不会变成黑块；
3. 取 `ImageData`，算出 `Uint8Array(15000)` 位图；
4. 页面显示的就是这块位图（预览与屏幕所见即所得），确认后才 `packet()` 组包上传。

`monochrome()` 会检查输入长度，`pixels()`/`packet()` 会检查位图长度，`decode()` 会校验 `RLG1`、宽高、负载长度和 CRC32 并抛出中文错误，所以页面在数据不合法时能给出具体原因而不是白屏。

设备侧只有一条 `scratch` 缓冲（16KB，优先 `heap_caps_malloc(MALLOC_CAP_SPIRAM)`，失败退回内部 RAM），`WebServer` 的 upload 回调直接往里追加，长度超过 15016 立即返回 413，收到不完整数据返回 400 且**不覆盖**当前照片。校验或存储失败不会替换当前照片；若文件已经保存、但屏幕刷新失败，设备返回 503，重启后可重新读取该 SD 文件。

## 调节

`gallery_config.h` 集中了可调项：

- `GALLERY_AP_SSID` / `GALLERY_AP_PASSWORD`：热点名与密码（WPA2 至少 8 位 ASCII；改密码后帮助页会同步显示）。
- `GALLERY_MAX_PHOTOS`：24，`static_assert` 限制在 99 以内，因为文件名是 `P%02u`。
- `GALLERY_WIDTH` / `GALLERY_HEIGHT`：本板固定为 400×300，前端也使用同样的尺寸，不是只改头文件就能适配其他屏幕。
- `GALLERY_UPLOAD_TIMEOUT_MS`：15000，上传中途断线的兜底清理时间。

## 文件结构

- `12_photo_gallery.ino`：只有 `setup()`/`loop()` 两行转发。
- `gallery_app.cpp`：热点、DNS、HTTP 路由、状态 JSON、上传状态机、按键与幻灯片调度、帮助页/照片绘制。
- `gallery_config.h`：全部常量与 `static_assert`。
- `gallery_packet.h`：`RLG1` 数据包读写、`galleryValidate()`、`galleryCrc32()`。
- `gallery_store.h/.cpp`：SDMMC 挂载、槽位扫描校验、临时文件保存与回读校验、删除、错误信息。
- `gallery_image.h`：浏览器端像素处理 JS。
- `gallery_web.h`：画廊页面（HTML/CSS/JS 全内嵌，不引用任何 CDN）。
- `board_pins.h`、`display_bsp.*`、`draw_bsp.*`、`buttons_bsp.*`、`font8x8.h`：板级与显示/绘图/按键基础层。

## 排障

- **屏幕一直空白或 `PANEL_INIT: FAIL`**：`displayReady=false`，页面会显示「屏幕未就绪」，所有上传返回 503。检查 SPI 接线后重启。
- **提示临时模式**：未插 SD、卡不是 FAT32 或挂载失败。此时只有一张 RAM 临时照片，重启会丢失。需要保存时，先断电，检查并备份 SD 卡，再插卡重启；不会自动迁移当前 RAM 照片。
- **上传返回 400**：数据长度/尺寸/CRC 不符，通常是传输中断，重新上传即可。
- **上传返回 409**：24 个槽位已满，先在相册里删几张。
- **缩略图显示「损坏」**：卡上的文件校验失败，可以删掉重传；这类文件不会被 `nextPhoto()` 翻到。
- **手机打不开页面**：确认连的是 `RLCD-Gallery` 而不是家里的 Wi-Fi；Android 可能弹「无互联网」提示，选「仍然连接」。
- **页面能开但上传卡住**：热点被其它设备占满或手机切回了蜂窝网络，重连热点后重试。

## 已知限制

- 热点只有 WPA2 口令保护，没有账号体系也没有 HTTPS：拿到密码的人都能上传和删除照片。
- 24 张占约 352KB SD 空间，界面不做分页，全部缩略图一次性加载。
- 幻灯片由设备主循环推进，不要求浏览器保持打开；重启后不保留幻灯片设置，上传和网络请求可能推迟切页。
- 本示例只做「手机 → 屏幕」的展示，不含设备端拍照、相册导出或 EXIF 保留。
- 本轮已恢复远端的 SD/RAM 存储逻辑，保留注释、排版和入口编号整理；仅执行静态核对与前端脚本检查，未重新编译或烧录，需开发者上板复验。

上板验收建议覆盖：插卡全流程上传/切换/删除/幻灯片、不插卡临时模式、满 24 张后上传、拔卡后重启、上传中断（中途切飞行模式）、损坏文件、长按 KEY 帮助页、以及断电重启后选中张号的恢复。
